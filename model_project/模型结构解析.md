# 模型结构解析

更新时间：2026-06-04

## 目标定位

当前模型项目不定位为简单的“PlantRG 抗性基因分类器”，而定位为跨物种抗性基因预测 benchmark 和模型框架。核心问题是：模型能否在未见过的物种、属或科中识别抗性基因，并且相对传统 HMM/domain 方法是否有稳定优势。

推荐论文主线：

> PlantRG-Bench：面向植物抗性基因预测的跨物种基准数据集与蛋白语言模型框架。

## 数据输入

当前已有输入：

- PlantRG protein FASTA：787 个文件；
- PlantRG CDS FASTA：787 个文件；
- 完整 manifest：`../metadata/plantrg_full_manifest.csv`；
- 数据说明和下载记录：`../PlantRG_data_introduction.md`。

后续需要补充：

- 非抗性基因负样本 proteome；
- Pfam/HMMER 或 InterProScan 结构域注释；
- 外部验证集，如 PRGdb、PlantNLRatlas、已克隆抗性基因集合；
- 物种分类信息，用于 species/genus/family split。

## 数据流

建议数据流分为 6 层。

### 1. 原始序列层

输入：

- protein FASTA；
- CDS FASTA；
- manifest。

处理：

- 解析 FASTA；
- 标准化 gene ID；
- 统计序列长度；
- 检查异常字符；
- 检查空序列；
- 建立 CDS-protein 配对表。

输出：

- clean protein table；
- clean CDS table；
- species-gene manifest；
- 数据审计报告。

### 2. 标签层

正样本：

- PlantRG 中的抗性基因序列。

负样本：

- 从同物种或近缘物种 proteome 中抽取非抗性蛋白；
- 过滤含有明显抗性相关 domain 的蛋白；
- 尽量做长度和物种分布匹配。

可选多分类标签：

- NBS；
- CNL；
- TNL；
- RLK；
- RLP；
- 其他 domain 组合类别。

如果 PlantRG 无法提供逐基因 family/domain 标签，则用 HMMER/Pfam 重新注释。

### 3. 去冗余和数据划分层

必须避免同源泄漏。建议使用 MMseqs2 或 CD-HIT 进行聚类。

数据划分：

- random split：用于和常规研究对比；
- sequence cluster split：避免高相似序列跨训练和测试；
- leave-one-species-out；
- leave-one-genus-out；
- leave-one-family-out。

评价重点应放在跨物种和跨谱系划分，而不是随机划分。

### 4. 特征层

建议至少包含 4 类特征。

#### k-mer 特征

- amino acid k-mer；
- CDS nucleotide k-mer；
- codon usage；
- GC 含量；
- 序列长度。

优点：简单、可解释、计算成本低。

缺点：跨远缘物种泛化可能有限。

#### domain 特征

- Pfam/HMMER 命中；
- domain presence/absence；
- domain count；
- domain order；
- NBS/LRR/TIR/CC/Kinase/TM 等关键结构域组合。

优点：生物学解释强，是强 baseline。

缺点：对非典型抗性基因和远缘新型 domain 组合可能不足。

#### 蛋白语言模型 embedding

候选：

- ESM；
- ProtT5；
- ESMC/ESM2，视本地环境和 GPU 条件决定。

策略：

- 先不直接微调整个大模型；
- 先提取 embedding；
- 用 LightGBM、Logistic Regression、MLP 做下游分类。

优点：泛化能力强，适合跨物种评估。

缺点：需要 GPU 或较长 CPU 时间；embedding 文件较大。

#### 融合特征

组合：

- protein embedding；
- domain 特征；
- CDS/codon 特征；
- 物种或谱系信息仅用于分析，不建议作为模型直接输入，避免模型记忆物种偏差。

## 模型结构

### 基线模型 1：Domain Rule / HMMER

目的：

- 建立传统方法基线；
- 检查深度模型是否真正优于 domain 规则。

输入：

- HMMER/Pfam domain 注释。

输出：

- R gene / non-R gene；
- 可选 family 分类。

### 基线模型 2：k-mer + LightGBM

目的：

- 提供轻量、可复现、无需 GPU 的机器学习 baseline。

输入：

- amino acid k-mer；
- CDS k-mer；
- 长度和组成特征。

输出：

- 二分类概率；
- 可选多分类概率。

### 主模型 1：Protein LM embedding + LightGBM

推荐作为第一版主模型。

结构：

1. 使用 ESM/ProtT5 提取每条 protein 的 fixed embedding；
2. 对 embedding 做 mean pooling 或模型默认 pooled representation；
3. 输入 LightGBM 或 Logistic Regression；
4. 输出 R gene 概率。

优点：

- 实现相对稳；
- 训练成本低；
- 容易与 baseline 公平比较；
- 适合 CPU 训练，下游分类可放 q07。

### 主模型 2：Protein LM embedding + MLP

结构：

1. protein embedding；
2. 2-3 层 MLP；
3. dropout；
4. sigmoid/softmax 输出。

适用：

- 数据量足够；
- 希望和 LightGBM 对比；
- GPU 可用时可加速。

### 扩展模型：多特征融合模型

结构：

- protein embedding 分支；
- domain 特征分支；
- CDS/codon 特征分支；
- concat 后输入 MLP 或 LightGBM。

用途：

- 检查 domain 和 CDS 信息是否能补充蛋白 embedding；
- 做 ablation study。

## 评价指标

二分类：

- AUROC；
- AUPRC；
- precision；
- recall；
- F1；
- MCC；
- calibration。

多分类：

- macro-F1；
- weighted-F1；
- per-class recall；
- confusion matrix。

跨物种评估：

- per-species performance；
- per-genus performance；
- per-family performance；
- 与进化距离或训练集中近邻相似度的关系。

## 关键消融实验

至少建议做：

- random split vs species split；
- 去冗余前 vs 去冗余后；
- k-mer vs domain vs protein embedding；
- ESM vs ProtT5；
- protein only vs protein + domain；
- 是否加入 CDS/codon 特征；
- 负样本构造策略对性能的影响。

## Slurm 执行策略

CPU 任务：

- 使用 `q07` 分区；
- 每个任务最多 30 核、150G 内存；
- 每次最多提交 6 个命令；
- 使用 `mamba run -n bio3`。

示例：

```bash
sbatch -p q07 -c 30 run.sh
```

适合放 Slurm 的任务：

- FASTA 解析和统计；
- HMMER/Pfam 注释；
- MMseqs2/CD-HIT 去冗余；
- k-mer 特征提取；
- LightGBM/传统 ML；
- 大规模评估和 bootstrap。

GPU 任务：

- 由用户自行执行；
- 包括 ESM/ProtT5 embedding 提取和可能的深度模型训练。

## 风险点

- 负样本构造不严谨会削弱论文可信度；
- 不做同源去冗余会造成性能虚高；
- 只报 random split 不够；
- PlantRG 标签来源本身可能是预测结果，不能当作完全实验真值；
- 没有外部验证集时，文章说服力会不足；
- 没有病虫害表型标签时，不能宣称模型预测具体抗病性。
