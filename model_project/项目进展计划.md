# PlantRG 模型项目进展计划

更新时间：2026-06-04

## 项目定位

当前项目不建议定位为普通“抗性基因分类器”。更合适的论文方向是：

> PlantRG-Bench：面向植物抗性基因预测的跨物种基准数据集与蛋白语言模型框架。

该方向的核心价值在于把 PlantRG 数据库转化为可复现 benchmark，并系统评估随机划分、跨物种划分和跨谱系划分下模型性能的差异。

## 当前关键判断

- PlantRG 数据完整性足够支持后续 benchmark 构建。
- protein 序列质量更适合作为第一版主模型输入。
- 修正后 protein 正样本保留率较高，足够支撑第一版 benchmark。
- CDS 序列有非标准字符和潜在污染，需要严格清洗后再用于补充分析。
- 只做随机划分容易高估模型性能，论文必须强调跨物种和跨谱系泛化。
- 负样本构建和同源去冗余将决定 benchmark 是否可信。

## 下一阶段计划

### 阶段 2：训练数据清洗

- 已构建 protein 严格清洗表。
- 已排除含 `.` 和内部 `*` 的 protein 记录。
- 已剥离末端 `*` 终止符。
- 已统计清洗前后每个物种保留数量。
- 已生成可追溯的正样本索引表。
- 下一步：检查 FASTA header 是否可提取抗性基因亚类标签。

### 阶段 3：负样本构建

- 确认可用外部植物 proteome 数据源。
- 优先选择与 PlantRG 物种匹配或近缘的植物 proteome。
- 排除已知抗性基因和高相似同源序列。
- 控制长度分布，避免模型只学习长度偏差。
- 输出正负样本比例可配置的数据集。

### 阶段 4：去冗余与划分

- 使用 MMseqs2 或 CD-HIT 做序列相似性聚类。
- 构建 random split、species split、genus/family split。
- 保证测试集与训练集之间的同源泄漏最小化。
- 记录每个划分的物种、序列数和聚类分布。

### 阶段 5：baseline 模型

- k-mer + logistic regression / random forest。
- domain/HMM rule baseline。
- 蛋白语言模型 embedding + 轻量分类器。
- GPU 微调任务暂缓，等需要时由用户执行。

### 阶段 6：论文分析

- 比较不同划分策略下的性能差异。
- 分析随机划分是否明显高估性能。
- 评估 protein language model 相比传统特征的收益。
- 做错误案例、motif/domain 和跨物种泛化解释。
